# Shopify unpaid manual cancellation

This phase 4 service cancels only untouched unpaid Shopify orders after an explicit merchant action. It is separately disabled by default through `SHOPIFY_ORDER_OPERATIONS_ENABLED`, in addition to bridge, write, shared-capacity and payment-operation gates. The existing EverShop cancellation remains in its own native order transaction. Shopify cancellations never create counterfeit EverShop orders.

`createCancellationService` accepts the authenticated client, private mapping store, optional quote repository, reviewed location GIDs, order observation and central-capacity adapters. The private admin endpoint is `POST /api/shopify/orders/operation`. `cancel` needs the native order GID, stable operation key, merchant confirmation and reason. `reconcile-cancel` reads the original journal and job; it does not resend cancellation. Only an authenticated native admin may invoke the endpoint.

## Native acceptance and durable proof

Admin GraphQL is pinned to `2026-10`. The initial read requires the configured shop, a noncapturable PENDING order, complete unchanged quantities, manual pending SALE transactions, no payment details, no refunds or fulfillments, zero native received money and outstanding equal to total. Independently registered receipts and unresolved quote/payment/shipment operations block cancellation. Paid, card, authorized, partial-payment, edited or complex orders require merchant review. This strict subset avoids Shopify's automatic voiding of authorizations during cancellation. The mutation explicitly uses `notifyCustomer:false`, `refundMethod:{originalPaymentMethodsRefund:false}` and `restock:true`, using the current refund-method input rather than deprecated `refund`.

One private `order-restock:<OrderGID>` record freezes the original request, hash, merchant operation key, complete lines, fulfillment allocations and approved active location versions. It moves through prepared, in-flight, pending, unknown, review or complete. Quote invalidation increments its payment version and clears the Wise URL under the same durable order lock used by payment and shipment services. All later finance/shipment actions reject an existing cancel intent, including terminal completion. No customer message or financial transfer is sent.

The original intent becomes durable before the native mutation. An unknown response retains that intent and freezes its central SKUs; there is no blind retry with either the same or a new operation key. A known asynchronous `OrderCancelJobResult` is polled at most three times per invocation. A pending job can be reconciled through the original action. Completion needs the original job/order identity, SUCCEEDED status and no job errors, followed by unchanged native quantities, zero received money, a canceled order and unchanged approved active location facts. Shopify can successfully cancel an unpaid order without restocking an inactive location; therefore canceled status alone is insufficient. Location updates during the job cause review rather than invented replenishment.

The completed per-line restock proof is committed before order ingestion. Inbox processing defers an ambiguous cancellation while its trusted original intent is pending. Once proof is complete, the normal transactional order-line business keys release each quantity once and additive mirrors repay any inventory debt first. A crash after saving proof safely retries ingestion. Failed or ambiguous native outcomes remain frozen for investigation; neither the cron nor reconciliation resets stock to 999.

## Verification boundary

Synthetic regressions cover quote invalidation before mutation, proof before release, pending-job readback, lost responses, no mutation replay, inactive or changed locations, incomplete allocations, paid/card/authorization/receipt rejection, crash recovery and all five private API gates. Separate disposable PostgreSQL regressions cover cumulative duplicate/order changes, debt repayment and deferred cancel inbox delivery. These establish code behavior, not actual provider cancellation, restocking, refunds, notifications or live financial acceptance.

Shopify does not expose a conditional order version on `orderCancel`. The bridge's order lock serializes its own operations, while an external native writer can still change an order between reads and the mutation. Keep the initial Shopify store on reviewed manual payment methods and operate these actions through the bridge. Changed readback fails closed. Authenticated provider acceptance and production-copy rehearsal are still required before enabling this gate.
