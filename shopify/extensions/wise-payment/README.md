# SHUSHA native customer-account payment entry

This is a native Preact customer-account UI extension, using Shopify's `s-*` web components. It targets the account order-status block and the order action menu, so the verified payment entry is available from both order details and the owned order list. It does not customize hosted checkout or act as a card payment gateway.

Admin GraphQL uses `2026-10`. Customer-account UI independently pins the currently published official `2026-07` API and `@shopify/ui-extensions@2026.7.0`; no unpublished `2026-10` UI SDK is assumed. Dependencies and their lockfile are fixed. `npm ci --ignore-scripts` followed by `npm run build` verifies local bundling without registration or deployment.

The tracked TOML is an empty, unregistered template. In the authorized private Shopify app project, use Shopify CLI to generate/register the extension UID, copy these source modules and settings into its generated configuration, and leave the store password protected. Review the generated UID/app association before preview or deployment. No app UID, client secret, backend origin, customer data or bank information is included here. Configure `backend_origin` as the verified HTTPS backend origin in the accounts editor only after backend authentication is ready. Enable and obtain approval for the extension's network access capability and the app's protected customer access. Add the payment block in the accounts editor; the order-menu target is static.

The UI requests `POST /api/shopify/payment-access` with a fresh `shopify.sessionToken.get()` bearer token and `{orderId}`. Only a signed customer subject, matching app/store, verified native order ownership and unchanged active quote can return `{data:{paymentUrl,expiresAt,quoteRevision}}`. The helper accepts that envelope and rejects root-only, malformed or mixed success/error responses. Shopify's session token uses the shop hostname as `dest`, the app client ID as `aud`, and a Customer GID as `sub` when the customer is signed in and protected customer access is approved. Missing subjects fail closed. The short URL opens the private backend's `/shopify/payment` page. The UI holds it only in memory, refreshes before expiry and never logs it. Anonymous/pre-authenticated viewers cannot obtain instructions; the block asks them to sign in. Pending, already received, cancelled, unauthorized or changed quotes render no payment entry, with a generic unavailable message. The backend remains authoritative.

Shopify controls button appearance, focus behavior and responsive sizing; arbitrary CSS or custom SVG is unavailable in this surface. The order block uses a full-width primary native button. Wise's local Iconify SVG remains on the separately authenticated merchant payment page and the native theme.
